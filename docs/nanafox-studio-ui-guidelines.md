# NanaFox Studio UI 规范

> 状态：2026-08-29 基线。实现以 `src/studio/studio.css` 和已上线页面为准；本文记录视觉与响应式约束，避免 Demo、用户端和运营端继续分叉。

## 1. 设计方向

- 品牌气质：深色、克制、电影感，创作内容优先于装饰。
- 用户端强调简单任务流：找灵感 → 创作 → 查看作品 → 购买额度。
- 运营端可以提高信息密度，但继续复用相同颜色、字体、圆角、按钮和状态语义。
- 不为追求“设计感”增加无功能装饰、手绘图标或新的视觉体系。

## 2. 代码与设计工具边界

- 运行时 UI：React、项目 CSS、Phosphor Icons；不依赖 Figma、Pencil 或外部组件库。
- 当前 MVP 的事实来源是代码中的 CSS 变量、共享类和浏览器验收截图。
- Figma/Pencil 用于全新页面方向、多人评审或正式设计交付，不作为运行时组件，也不重复维护一套与代码脱节的组件库。
- 同一交互或样式出现两次以上时优先复用现有类；只有出现复用行为和状态逻辑时才拆 React 组件。

## 3. 基础视觉变量

统一使用 `studio.css` 的 `:root` 变量：

- 页面：`--page`
- 主面板：`--surface`
- 次级面板：`--surface-soft`
- 边框：`--line`、`--line-strong`
- 文本：`--text`、`--muted`
- 品牌与状态：`--blue`、`--blue-bright`、`--teal`、`--danger`

新增颜色前先确认现有变量不能表达该语义。禁止引用未定义 CSS 变量。

## 4. 共享界面规则

- 主操作按钮、输入框、卡片、弹层、Modal、头像、状态标签沿用现有共享类。
- 图标只使用 Phosphor Icons，文字按钮必须保留可理解的文本或 `aria-label`。
- 可点击目标在移动端至少 44 × 44 px，并保留 `:focus-visible`。
- 弹层必须提供 `aria-expanded`、对应控件关系和明确名称。
- 临时弹层支持点击外部和 `Esc` 关闭；Modal 打开时同时锁定页面根节点与正文滚动。
- 邮箱、用户 ID、订单号等外部文本所在的 flex/grid 子项必须设置 `min-width: 0`，并按场景换行或省略；完整值通过页面详情或 `title` 可见。

## 5. 响应式规则

固定验收宽度：1440、1024、720、390、320 px。

- 桌面：顶部主导航和完整运营侧栏。
- 720 px 及以下：底部导航；头部账户与额度弹层右侧保留 12 px，最大宽度 320 px，避免极窄屏裁切和大屏手机过宽。
- 页面根布局不设置 320 px 最小宽度，也不用 `100vw` 撑满滚动页面，避免纵向滚动条诱发横向滚动。
- 固定底栏必须叠加 `env(safe-area-inset-bottom)`，页面正文预留同等安全区。
- 禁止仅通过隐藏核心字段解决窄屏溢出；表单、额度、支付和用户身份必须仍可读取和操作。

## 6. 页面验收清单

每次 UI 改动至少检查：

1. 登录、注册和找回密码。
2. 首页创作表单、生成中、失败和额度不足状态。
3. 灵感列表与详情、作品和最近删除。
4. 额度套餐、支付订单和账户设置。
5. 运营总览、用户加额、套餐价格、灵感和支付渠道。
6. 长邮箱、长用户 ID、长套餐名、空数据、错误和加载状态。
7. 320 px 无裁切，桌面无视觉回退，键盘焦点可见，浏览器控制台无新增错误。
